## 操作

書房由 `/` 登入後分為「書房書展列表」與「教會自辦書展」，按建立者分類，歸屬教會與建立者分開保存。點場次先看出貨單號、日期、金額與付款方式，再點單號查看及修改。每場有結帳、交易與營收、商品數量、計算機四個工作區。封存場次持續保留，可由書房重新開啟。書房整頁採大地色，教會整頁採藍灰色，包含收銀 iframe。

教會密碼由書房的「教會入口」設定，客戶代碼 AA01 對應 `/aa01`。伺服器每次請求驗證角色與場次所屬教會。515 筆客戶只使用代碼、名稱與會計匯出所需欄位，原客戶檔的地址、聯絡、餘額等欄位未發布。

所有場次新加入商品依序採用「單品設定（含 73 個原雲 POS 特價）→ 官網售價 → 類別設定（含 34 個原分類折扣）→ CSV 原價」。單品及類別可設定百分比或固定單價，日期留白為永久有效，起訖日均包含當日（臺灣時間）。商品設定只由書房操作，以 D1 settings 保存並做版本衝突檢查；開啟中的收銀台每分鐘檢查更新，既有成交單與已保存草稿不自動重定價。

掃碼與名稱／代碼搜尋共用一個輸入欄。常用商品由搜尋結果的星號加入或移除，存入本場書展的雲端共用設定；不同場次分開。購物車使用精簡商品列與數量加減鈕，點「編輯」或連點商品兩下可修改單價、數量、折扣（79 為七九折），可套用同分類折扣。手動修改優先於預設特價。

日結介面改成純加減乘除計算機，可帶入本場有效交易的現金淨額，含混合付款與退款。計算不寫入交易。過去日結資料及備份相容 API 保留，完整場次備份仍可取得舊紀錄。

商品數量由書房管理，可以上傳 CSV 或貼上每行 `商品代碼,數量`，支援加減與設定。教會只看配置、已售與目前數量，不能修改或匯入；伺服器也會拒絕教會修改庫存。庫存可以不建立，負庫存不阻擋收銀。

書房從兩種書展列表進入各場查單，也可在場內快速切換。教會只看自己的場次。教會收款僅提供文化幣、LINE PAY 及兩者混合；書房保留現金與信用卡。CSV、Pilot 與完整備份由書房操作。「教會入口」每列可修改密碼或選擇該教會場次管理庫存，空場次提示教會先自行建立，書房不能替教會建立結帳場次。教會新增時預設名稱為代號加臺灣建立日期（如 AA0120260913），可自行修改名稱、封存及重新開啟。書房在教會自辦場次只能匯入庫存、查看及會計匯出，不能更動交易。

書房建立的書展一律使用 `PF202609080001` 格式，即 PF＋台灣交易日期 YYYYMMDD＋至少四碼流水號，即使該場歸屬教會亦同。教會自己建立的場次使用 `AA01202609080001` 等獨立教會流水號。書房跨場次共用每日 PF 流水，各教會分開計數。修改保持單號、刪除不重用。舊號碼表保留，新的畫面號碼另存 shipment_numbers，原始訂單 ID 不變。

交易列表提供「刪除」與「修改」。修改可新增、替換、移除商品、改單價／數量／折扣／付款與備註，總額與庫存隨之更新；同時修改同一筆會提示衝突。原本已作廢紀錄保持原狀，封存場次須由原管理角色重新開啟才能修改。

## 保存與一致性

- Cloudflare D1 保存 events、churches、sessions、closings、audit、shop、settings 與 order_numbers。
- 每場 state 以訂單、草稿、參考數量與共用設定分鍵；提交採三方差異合併與資料庫 revision 比較交換。
- 兩筆不同訂單可並行保存；同一筆衝突回傳 409，避免靜默覆寫。
- 訂單內部使用 UUID，畫面及一般 CSV 使用每日流水單號；重送相同 mutation 可重試。結帳在伺服器確認前不顯示完成，失敗保留本機 recovery 並提示重試，不能重複收款。
- 伺服器核對交易明細總額與付款總額。雲端更新的舊 state 由同一資料庫 trigger 原子寫入 audit；刪除與清空仍保留修訂紀錄。
- 草稿依裝置分開，成交單跨裝置共用。每 15 秒讀取場次新狀態；背景讀取與儲存依序執行，保留讀取期間的掃描及原衝突基準。
- 既有日結快照持續保存；介面已由計算機取代。完整場次備份包含場次、修訂與舊日結。
- Pilot ERI 由伺服器分配全域不重疊序號範圍；原 exporter schema 與驗證保留。
- 密碼以 PBKDF2 SHA-256 100,000 次雜湊，session cookie 為 HttpOnly / SameSite Strict / HTTPS Secure；登入有限速；變更教會密碼撤銷原 session。

先前因教會禁止的付款方式而卡住的待存交易不再使收銀台白屏。資料保留在原裝置，可從「處理待存結帳」核對實際收款後重新保存，或保留資料登出交由書房處理。未完成保存仍禁止再次結帳，避免重複收款。

## PILOT 正式匯出

按 PILOT 匯出後輸入出貨日期、第一筆正式出貨單號及第一張發票。先產生預覽，逐列顯示來源交易、客戶／載具、TAXCATE、CODE、INVNO、日期，確認後下載三份原格式 CSV。瀏覽器阻擋多檔下載時，可逐一下載同一份已確認匯出。

正式匯出恢復原雲 POS 分組：同場次未填發票資料與預設捐贈碼 2995 合併為一組；有載具、統編或其他愛心碼的交易各自成組，即使載具或統編相同也不合併。每組使用一個 base CODE。混稅為主號與主號加尾碼 1；只有免稅仍使用主號。發票計數器獨立，每張 STKSALE1 遞增一次後八碼，超過範圍即停止。正式日期集中於 exportContext，套入四個 STKSALE1 日期欄與 STKSALE2.SDATE。

lib/pilot-core.mjs 的工廠函式由原 legacy 模組逐字擷取。正式匯出依原分組將來源交給同一核心處理。原稅別、客戶、載具、INVQTY、付款、PLUSSUB、VCHRPLUS、負數商品及金額計算均由原函式處理；合併後的稅額尾差仍按原規則計算。finalization 只允許變更正式識別、日期及使用者指定的發票旗標，逐欄比對其他業務欄位。每筆來源 identity 都保留到正式主單的 mapping，僅關聯自身有商品的稅別。預覽可展開合併單包含的原始出貨單號，POS 原始交易不合併也不改寫。

依使用者提供的 2026 年 STKSALE1.csv（8,172 張主單）與 STKSALE2.csv（30,266 筆明細）核對：具有 POSCODE 的交易均為 PAYCASH=1，電子發票資料均為 EINVFLAG=1、INVCATE=2。依要求，正式匯出所有主單固定使用這三個值，預覽顯示已勾選 POS 現銷與電子發票。原 CUSTOMER 與 POS 訂單不改寫。data/pilot-eri-history.json 僅收錄參考檔的既用 ERI，沒有匯入原交易內容；後續正式匯出避開這些識別碼。

每次新預覽分配全新 ERI，從全域持久計數器取號，避開目前來源、歷史 state／audit、過去正式匯出與本次已分配值。STKSALE2.MASTERI、VCHRPLUS.SRCERI 一併重建；VCHRPLUS.CODE 付款分類保持不變。ERI 與匯出快照存入 D1 的 pilot_eris、pilot_exports、pilot_export_parts。取消或失敗的預覽所用 ERI 也不再重用。正式 CODE、INVNO、ERI 不回寫原 POS 訂單。

確認前比對來源交易摘要；預覽後交易有變更時回傳 409，必須重做預覽。原自動每 20 筆會計匯出改成僅備份，正式會計下載一定經過輸入及確認。

## 開發與部署

Node.js 22.13 以上；`npm ci`、`npm run dev`、`npm run build`。首次本機測試需將 `drizzle` SQL 套用至本機 D1。`ADMIN_PASSWORD_HASH` 應由密鑰設定管理，不得提交密碼或 `.env`。

`npm run db:generate` 產生 schema migration。初始 migration 含 audit trigger，未來 migration 必須保留。`.openai/hosting.json` 僅存 Sites ID 與 DB binding。部署封裝須包含 `dist/.openai/drizzle`。

資料匯入工具 `node scripts/seed.mjs <CSV目錄>` 僅輸出必要商品及客戶欄位。更新收銀台、價格核心或 adapter 後執行 `node scripts/build-legacy.mjs`。`node --test tests/checkout.test.mjs tests/state.test.mjs tests/pos-core.test.mjs tests/orders.test.mjs tests/pilot-finalize.test.mjs legacy/tests/pilot-exporter.test.cjs` 執行運算、掃描處理、特價優先順序、常用商品、計算機、出貨單、刷新併發與正式匯出回歸測試。

登入的必要資料合併為一個 bootstrap；教會入口設定與同步進度改成背景載入。進入收銀台共用外層已載入的商品快取與場次請求，移除 iframe 重複下載商品及場次。草稿儲存直接更新營收摘要。新結帳保存使用已讀取的場次做首次 revision 比較，編號以單次 INSERT RETURNING 分配，省去三次資料庫往返；仍等待可靠保存才完成結帳，按鈕即時顯示保存中。尚未宣稱實機改善百分比。

## 測試邊界

無人值守使用已部署網站 `/pos/api/scheduled-sync`。每次雲端排程由 Sites get_site 取得目前 current_live_url 及受平台管理的 siwc_bypass_bearer_token；只對該 Site 發送 `OAI-Sites-Authorization: Bearer <token>` 與 `X-POS-Sync-Key: <token>`。伺服器以密鑰設定 SYNC_SERVICE_KEY_HASH 驗證 SHA256("pos-sync:" + token)，不信任入口代碼或瀏覽器身份。POST 反覆同步至 finished，busy 時等待再試；GET 讀回持久游標、cachedProducts 與 catalogSourceRevision。請求不帶客戶、訂單或付款資料，不建置或發布網站。憑證只留在記憶體與 stdin，禁止記錄、寫入排程提示或提交原始碼。若平台服務憑證輪替導致 401，停止並回報需重新綁定，不能放寬權限。

登入除每入口每 IP 12 次／10 分鐘外，另有每 IP 合計 60 次／10 分鐘限制。API 寫入驗證 Origin 及 JSON，禁止以 GET 登入、登出或修改。入口 Cookie 只送往 /pos，HttpOnly、SameSite Strict、HTTPS Secure。HTML／API 包含禁止索引、防 MIME 嗅探、同源嵌入及限定相機權限標頭。robots 與 noindex 只降低索引，資料保護以伺服器授權為準。
